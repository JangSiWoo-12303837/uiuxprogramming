# 면접 준비 서비스

예상 질문을 고르고 답변을 작성해 보는 면접 준비 웹페이지다.
로컬에서는 index.html을 브라우저에서 열면 된다.

1. GitHub Repository URL: https://github.com/JangSiWoo-12303837/uiuxprogramming
2. Published Website URL: https://jangsiwoo-12303837.github.io/uiuxprogramming/

## 사용자와 목표

- 사용자: 면접을 준비하는 취업 준비생
- 목표: 예상 질문에 대한 답변을 작성하고 부족한 내용을 찾아 보완한다.
- 핵심 행동: 질문 선택, 답변 작성과 기록, 답변 자기 점검
- 완료 조건: 답변을 기록한 뒤 자기 점검 결과와 보완할 내용을 확인한다.

## 사용자의 흐름

1. '예상 질문' 탭에서 질문을 고르고 '답변 작성 시작하기'를 누른다.
2. 답변을 입력하고 '작성한 답변 확인하기'를 누른다. 비어 있으면 같은 화면에서 수정한다.
3. 선택한 질문과 답변을 확인한다. 고칠 내용이 있으면 '답변 수정하기'로 돌아간다.
4. '답변 기록 완료하기'를 누르고 연습 기록에서 완료 안내와 답변을 확인한다.
5. '답변 점검하기'를 눌러 잘 지킨 항목을 체크하고 결과를 확인한다.
6. 결과를 참고해 답변을 보완하거나 '다시 연습하기'로 초기화한다.

## 7주차 인터랙션 시나리오

1. 질문 선택
   - 행동, 이벤트: 질문 종류를 바꾸고 '답변 작성 시작하기'를 누른다. (change, click)
   - 조건: 자기소개, 지원 동기, 장점과 단점 중 하나를 선택한다. 처음에는 자기소개가 선택되어 있다.
   - 반응, 다음 상태: 고른 질문을 답변 입력 화면에 보여준다. 질문을 바꾸면 입력 중이던 답변은 비워진다.

2. 답변 입력
   - 행동, 이벤트: 답변을 입력하고 '작성한 답변 확인하기'를 누른다. (input, click)
   - 조건: 공백 외의 내용이 있는가?
   - 반응, 다음 상태: 내용이 있으면 질문과 답변을 확인 화면에 보여준다. 비어 있거나 공백뿐이면 입력 방법을 안내하고 입력창에 테두리를 표시한다. 다음 화면으로 넘어가지 않는다.

3. 내용 확인과 수정
   - 행동, 이벤트: 질문과 답변을 읽고 '답변 수정하기'를 누른다. (click)
   - 조건: 확인한 내용에 수정할 부분이 있는가?
   - 반응, 다음 상태: 기존 입력을 유지한 채 답변 입력 화면으로 돌아간다. 고친 뒤 다시 확인하면 수정한 내용이 반영된다. 질문 선택으로 돌아갔다 와도 질문을 바꾸지 않으면 답변이 남아 있다.

4. 기록 완료
   - 행동, 이벤트: '답변 기록 완료하기'를 누른다. (click)
   - 조건: 확인 화면까지 진행한 상태인가?
   - 반응, 다음 상태: 연습 기록 탭으로 이동하고 초록색 완료 안내와 질문·답변을 보여준다. '기록한 답변 수정하기'를 누르면 기록했던 질문과 답변을 다시 가져온다.

5. 다시 시작
   - 행동, 이벤트: 완료 후 '다시 연습하기'를 누른다. (click)
   - 조건: 새 연습을 시작하려는가?
   - 반응, 다음 상태: 질문은 자기소개로 돌아가고 답변, 오류 안내, 확인 내용, 기록을 모두 지운다. 첫 단계인 질문 선택 화면으로 돌아간다.

## 7주차에 수정한 내용

6주차에는 탭 전환, 답변 입력과 기록, 이메일 신청 기능을 만들었다.
7주차에는 바로 기록하던 부분에 내용 확인 단계를 넣고, 이전 단계로 돌아가기와 다시 시작하기를 연결했다.
화면 위에는 현재 진행 단계를 표시했다.

## 중간고사: 답변 자기 점검

7주차에는 답변을 기록하고 확인하는 데까지 만들었다. 중간고사에서는 기록한 답변을 스스로 점검하고, 부족한 항목에 맞는 보완 방법을 보는 기능을 추가했다.

질문에 맞게 답했는지, 구체적인 경험이나 이유를 넣었는지, 간결하게 전달했는지 확인하도록 했다. 답변을 작성한 다음 무엇을 고칠지 생각하는 데 도움이 되도록 연습 기록 뒤에 연결했다.

### 새 기능의 동작

- 사용자 행동: 기록한 답변을 읽고 잘 지킨 항목을 체크한 뒤 '점검 결과 보기'를 누른다.
- 확인할 조건: 기록한 답변이 있는지, 세 항목 중 어떤 항목을 체크했는지 확인한다.
- 성공 반응: 체크 개수와 체크하지 않은 항목에 대한 보완 방법을 보여준다. 모두 체크하면 소리 내어 연습하라고 안내한다.
- 답변 없음: 먼저 답변을 기록하라는 안내와 '답변 작성하러 가기' 버튼을 보여준다.
- 체크한 항목 없음: 오류로 처리하지 않고, 세 가지 보완 방법을 모두 보여준다.
- 점검 닫기: 점검 영역을 닫고 다시 열 수 있게 안내한다. 체크와 결과는 유지된다.
- 선택 변경: 이전 결과를 숨기고 결과 보기 버튼을 다시 누르도록 안내한다.
- 다음 행동: '답변 보완하러 가기'를 누르면 기록했던 질문과 답변을 입력창으로 가져온다. 보완 후 다시 기록하면 이전 점검은 초기화된다.

'체크 지우고 다시 점검'은 체크와 결과만 지운다. '다시 연습하기'는 질문, 답변, 기록과 점검 내용을 모두 초기화한다. 다른 탭으로 이동했다 돌아오면 점검 내용이 유지된다.

### 중간고사 테스트 결과

로컬과 배포된 페이지를 Chromium 브라우저에서 확인했다.

| 확인한 경로 | 결과 |
| --- | --- |
| 답변 없이 점검하기 | 안내가 나오고 답변 작성 화면으로 이동할 수 있었다. |
| 정상: 답변 기록 → 항목 체크 → 결과 보기 | 체크 개수와 선택에 맞는 보완 방법이 나왔다. |
| 0개 체크 | 0개라는 결과와 보완 방법 3개가 나왔다. |
| 1개, 2개 체크 | 체크하지 않은 항목의 보완 방법만 나왔다. |
| 3개 모두 체크 | 모든 항목을 지켰다는 결과와 소리 내어 연습하라는 안내가 나왔다. |
| 결과를 본 뒤 체크 변경 | 이전 결과가 숨겨지고 다시 확인할 수 있었다. |
| 점검 닫고 다시 열기, 다른 탭에 갔다 오기 | 체크한 항목과 결과가 유지됐다. |
| 체크 지우고 다시 점검 | 체크와 결과만 지워지고 답변 기록은 남았다. |
| 다른 질문을 선택한 뒤 답변 보완하기 | 점검하던 기록의 질문과 답변이 입력창에 들어왔다. |
| 보완 후 다시 기록 | 새 답변으로 기록이 바뀌고 이전 점검이 초기화됐다. |
| 다시 연습하기, 새로고침 | 답변 기록과 점검 내용이 모두 지워졌다. |
| 1100px, 768px, 390px | 가로 넘침 없이 체크박스와 버튼을 조작할 수 있었다. |

배포된 페이지에서도 위 경로를 다시 확인했다. 기존 답변 기록과 이메일 신청도 정상 동작했고, 테스트 중 JavaScript 오류는 없었다.

## 참고

- 기록은 최근 답변 1개만 보여준다. 새로고침하거나 '다시 연습하기'를 누르면 사라진다.
- 질문 종류를 바꾸면 작성 중인 답변은 지워지지만, 이미 완료한 기록은 남는다.
- 이메일 신청은 실습용 화면이며 실제 저장이나 발송은 하지 않는다.
- 자기 점검은 직접 체크한 항목을 기준으로 한다. 답변을 자동으로 분석하는 기능은 아니다.
